コミット指定のresetは、現在のブランチの先端を指定コミットへ動かします。--softはインデックスと作業ツリーを維持し、--mixed（既定）はインデックスも指定先へ戻して作業ツリーを維持します。

--hardはインデックスと作業ツリーも指定先に合わせ、追跡ファイルの未コミット変更を破棄します。書き込みの邪魔になる未追跡ファイルやディレクトリも消す場合があります。共有済み履歴では通常revertを使い、ファイルだけならrestoreを先に検討します。

以下は互いに代替となる比較例で、連続実行しません。作業を別途保護した練習用リポジトリでのみ扱います。reset --hardにdry-runはありません。status、diff、diff --cached、logで対象を確認しても、破棄の危険はなくなりません。

## コマンド

```sh
# いずれか1つを比較する例。連続実行しない
git reset --soft 'HEAD~1'
git reset --mixed 'HEAD~1'
git reset --hard 'HEAD~1'
```

## 要点

softは先端、mixedは先端とindex、hardは作業ツリーまで変える。

## 付箋

### reset-lecture [講義]

hardは未コミットの変更を破棄。reflogで全部戻せません。

### reset-study

図の「先端」は現在のブランチが指すコミットです。soft/mixedでも共有済みのブランチを動かすと共同作業に影響します。resetは過去コミットを直ちに物理削除する操作ではありません。
